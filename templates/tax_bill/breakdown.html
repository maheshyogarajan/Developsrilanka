{% extends layout_template %} {% block title %}Tax bill breakdown — FIESTA{% endblock %} {# templates/tax_bill/breakdown.html --------------------------------- Day-0 Fix 2026-05-27 (audit C1). The /tax-bill//breakdown URL previously returned raw JSON with internal field names (engine_error, rule_id, audit_defensibility components) when a customer reached it from a browser. That was a customer-trust kill: the page exposed engine internals AND surfaced a flat Rs 0 bill caused by an unrelated YA-normalisation bug (C2). This template wraps the same data the JSON endpoint returns in a presented page. Internal field names are NEVER surfaced — every machine-name (engine_error, rule_id, S12-DEDUCTION-RATIO, etc.) is translated to a customer-readable sentence in the route layer or filtered out here. Sections: 1. Heading + back-link to the main tax-bill page. 2. If engine ran cleanly: bracket-by-bracket walk + relief + net tax. 3. If engine did NOT run cleanly: a calm "your bill is being prepared" fallback that NEVER prints the engine_error string verbatim. 4. Income summary by category (no Decimal types, no DB column names). 5. Deductions summary (count + total claimed). 6. Audit-readiness sentence (Strong / Moderate / At-Risk -> plain English, never the score number or the component machinery). 7. CTAs: download audit pack PDF + back to bill. JSON consumers (audit-pack PDF generator, integration tests, API callers) get served by the same route via Accept-header negotiation — this template is only rendered when the client sends `Accept: text/html` (or no JSON-explicit signal).
